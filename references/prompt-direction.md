# 分镜与生成素材提示词

本模块用于素材前期，不运行视频生成流水线。ViMax/OpenStory类参考仅贡献故事拆解、角色连续性、关键帧和镜头依赖方法；用户要求提示词时，完成提示词即可。

## 从原句拆资产

先确定镜头解释目的、视点、角色／物体身份、起末状态与阅读预算。全片共用角色表和视觉参数，逐镜只写差异；不要为了生成能力修改文案事实。GPT图片提供静态设计／关键帧，Gemini视频描述该画面的动作和机位，两者保持同一主体、材质、光向、画幅。

每条输出可直接独立使用，不要求用户自己补“同上”：

| 项 | 内容 |
|---|---|
| asset_id / scene_id / source_ids | 资产与原句对应；用途、真实素材或示意重建 |
| 规格与连续性 | 画幅、建议时长、参考图ID、人物身份／服装／年代、不可变特征 |
| GPT图片提示词 | 主体 + 具体场景与动作瞬间 + 景别／视点／构图 + 光线／色彩／材料 + 主体位置及文字留白 + 需避免的错误 |
| Gemini视频提示词 | 输入关键帧 + 主体动作顺序 + 相机起点／运动／终点 + 速度和停留 + 环境响应 + 连续性约束 + 结尾构图与转场余量 |
| 声音 | 环境声需求；旁白、字幕与音乐由Remotion独立管理，除非项目另有要求 |
| 回到工程 | 文件命名、预期尺寸／时长、收到实物后的核对点；未生成标pending |

关键帧中需精确的中文、数据、logo或UI文字由Remotion排版或真实素材提供；生成提示词预留位置。情绪词须对应可见的光、景别、动作和材料，不能只写“高级、电影级、震撼”。不虚构服务参数；Gemini是用户指定的目标工具，实际可选视频模型与时长以届时工具支持为准。

## 按需要选参考

- **Awesome Opus案例 / opus-video-prompts**：查相似叙事或视觉机制，登记具体案例链接；它们多数是动画代码提示，不直接当生成式视频模型提示。
- **Lemo**：按故事语气选材质、构图、镜头语言；保留一套统一风格，不逐镜换影片类型。
- **ViMax**：故事 → 场景 → 镜头 → 角色表 → 关键帧 → 动作衔接。仅产出上表，不调用原项目agent/provider/生成器。
- **awesome-seedance**：用户指定Seedance时追加对应版动作、机位和约束；不以此覆盖GPT/Gemini交付。
- **Hypit**：有参考视频时抽取语义拍、字幕/B-roll/动作层和锚词，改写成符合自己文案的结构；参考文件未拿到或未看过就说明分析边界。
- **国风、手绘、穿搭**：按专门文案触发对应来源，只吸收角色一致性、分镜和画面方法；镜头最终进入Remotion。

若用户随后明确要求生成，使用当前可用的图像／视频工具落实，检查输出并更新素材状态。参考项目存在不代表模型、账户、额度或本地GPU已经可用。
